# Семантические адреса глав и упражнений

Адреса глав и упражнений остаются на числовом первичном ключе: `/chapters/3`, `/exercises/8`. Переход на путь в дереве (`/chapters/1.1.2`) или на любую другую «читаемую» схему — вне области работ.

## Почему это вне области работ

Предложение выглядит бесспорным улучшением, и по существу оно верное: адрес `/chapters/3` не соотносится ни с номером главы, ни с чем-либо ещё, что видно снаружи. Число — это `id` записи, присвоенный в порядке вставки при сидировании. Модель к смене готова: `path` уникален и осмыслен.

Против — не техника, а цена ошибки:

**Адреса проиндексированы, и весь органический трафик сайта идёт через них.** Главы и упражнения — основной вход из поиска. Смена схемы означает 301-редиректы со всех старых адресов и период, когда поисковик переносит вес на новые. Сделать это вслепую нельзя: нужен человек, разбирающийся в SEO, и доступ в Яндекс.Вебмастер и Search Console, чтобы видеть, что происходит с выдачей. Ни того, ни другого у проекта сейчас нет.

**Сайт может переехать на другой домен.** Пока это не решено, менять адреса второй раз подряд — гарантированно потерять больше, чем даёт читаемость.

**Выигрыш не покрывает риск.** Читаемый адрес — удобство, а не функциональность. Потеря позиций в выдаче для проекта, вся ценность которого в том, что его находят по запросам про SICP, — потеря пользователей.

```php
// Маршрут привязан к id — это работает как устроено, а не как дефект:
// /chapters/3  → запись с id = 3, то есть подраздел 1.1.1
// /chapters/16 → Глава 1.2
// Закономерности «номер в адресе = номер главы» здесь нет и никогда не было.
```

## Что к этому не относится

Соседние претензии, которые часто приходят в одной заявке с этой, областью работ **не** исключены:

- **Одинаковые `<title>` и `<meta description>`** на всех страницах — настоящая проблема, отслеживается в плане фазы 2 миграции (#1979, пункт 7).
- **Временные редиректы 302 вместо 301** при отбрасывании префикса локали по умолчанию — открытый тикет #1390.

Если решение по домену будет принято и в проекте появится человек с доступом к панелям вебмастера, этот файл стоит удалить: причина отказа исчезнет вместе с ними.
